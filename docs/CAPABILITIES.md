# 功能与能力边界

本文说明当前实现的功能、依赖和责任边界。详细契约以 [API 参考](API.md)、[Skill 结构化报告](SKILL_REPORTS.md)和[数据与恢复](DATA_AND_RECOVERY.md)为准。

## 功能总览

| 能力 | 已实现行为 | 使用边界 |
| --- | --- | --- |
| 持久任务 | New、连续 Turn、停止、Resume、Reset、Complete、Restore；保留执行与审计历史 | 平台只运行 Codex；继续和恢复跟随 Task 当前最新 Session |
| Task 业务分类 | 创建、编辑和 API 支持 `project`、`testType`、`tags`；`testType` 区分 Feature 测试和回归测试；历史任务默认 `regression` | 分类属于任务元数据，不自动选择业务 Skill、测试范围或部署流程；筛选作用于页面已加载的任务 |
| 版本周期与 Cron 系列 | API 创建提测版本周期和 Cron；每天生成独立 Task；版本页按周期查看 Task；关闭周期停止后续创建 | 每个 Task 在启动时自行拉取最新代码、镜像和环境；周期不冻结测试快照，已创建 Task 不因关闭周期而停止 |
| 版本周期数据分析 | 按 Feature/回归分组比较原始 initial、rerun 目标 initial 与 `rerun-1` 的 Pass/Fail、恢复、持续失败和回归趋势 | 部分 Step Pair 的 Task 单独标记为 partial，不计入完整周期汇总 |
| 并发 | 不同 Task 和同一工作目录内的多个 pytest 可并行 | 业务侧必须为每个 Run 分配独立日志、HTML、视频和下载路径；平台隔离托管资源，不能修复源文件互相覆盖 |
| 后台推进 | 登记 PID/LOG/DONE/STATE/META；运行期间 Worker 轻量观察，终态后恢复 Session 执行结果收集 Turn | 下一步部署、测试、业务 Rerun 和失败分析由任务指令与业务 Skill 决定；轻量检查本身不调用模型 |
| 执行归因 | `codex-skill-use` 自动记录真实调用、Skill 冻结版本、退出状态；后台和调度继承关联 Skill | 未通过包装器声明的调用不靠命令关键字猜测；可用 Skill 快照不等于实际使用记录 |
| 结构化报告 | Schema v2、追加 revision、业务轨迹、每 Run 多份 HTML、Fail Markdown、归档重试 | 发布者必须关联正确的 External Attempt；普通摘要和 Section 路径不等于 artifact 登记 |
| 测试中预览 | 已登记且已生成的 HTML 可读取当前快照，包括带 pytest-html 刷新按钮的版本 | 依赖业务源文件；刷新才读取后续内容；预览可打开不表示执行结束或归档成功 |
| 终态报告 | HTML、引用日志和媒体复制到平台，改写受控链接；后续未变化的 artifact 可复用 | 只处理受支持的引用图；缺失文件、未挂载文件和浏览器不支持的编码不能由归档自动补齐 |
| 大报告加载 | HTML 协商 gzip；无媒体用例省去隐藏播放器；分批显示、复用行、释放筛选掉的行；Video Check 回收详情缓存 | 保留全部用例和内容；内存随筛选结果规模变化；已知历史脚本提供兼容，其他版本使用原渲染方式；媒体与 Range 不压缩 |
| Viewed 共享 | 已托管 HTML 的视频点击状态按 artifact 存 SQLite；其他电脑重新打开或刷新可见 | 不区分查看人，不代表已看完；本地直接打开 HTML 使用插件的浏览器存储，不跨电脑共享 |
| 终端 | Codex CLI 实时输出、重连、只读 transcript 回放、完整原始输出下载 | 浏览器保留有限回放窗口和滚动缓存；达到缓存上限淘汰旧内容，继续接收新输出 |
| 运行库存 | 盘点 Runtime 归属与磁盘估算；对可回收项异步删除并释放空间 | Runtime 回收与 Task 删除是不同操作；回收不删除平台报告、托管视频或任务历史 |
| 数据保护 | SQLite 固定只读快照、备份副本空页压缩、空闲时恢复检查点、完成 Task 30 天保留清理；备份默认各保留 1 份 | 数据库备份不含日志或 Runtime 文件；平台备份和检查点均不备份媒体文件、播放清单、切片、缓存或外部业务产物 |
| 云录制提测源码 | 完整 Release Task 使用独立 Session clone，记录 commit、源码根目录、manifest SHA 和原地归档状态 | 普通 `cloud-recording-test` 仍使用共享仓库；旧 Task 不迁移 |

## 报告在不同阶段的行为

| 阶段 | 页面入口和读取来源 | 状态含义 |
| --- | --- | --- |
| 已登记、文件未生成 | 显示登记项；打开时返回 `404` | 知道预期输出路径，尚无可读文件 |
| External Attempt 运行中、HTML 已生成 | 登记 URL 返回 `private, no-store` 快照；可见刷新按钮不阻止打开 | 仅代表当前已有内容可预览 |
| 文件为空或没有 HTML 文档结构 | 直接请求返回 `409`；终态登记响应会标记 `available=false`，页面不生成打开入口 | 不把空文件或标题占位当作报告 |
| External Attempt 终态、HTML 仍有活动刷新按钮 | 登记 URL 继续返回 `200` 预览；终态归档仍要求完整报告 | 预览可用和归档完整分别判断 |
| 归档排队、处理中或部分成功 | 未托管 HTML 继续预览源文件；每份文件及依赖发布后，原 URL 自动转到正式 artifact | 其他文件按作业重试，不阻断已可用报告 |
| 归档成功 | 正式 artifact URL 读取托管版本；原登记及资源链接自动转到对应归档 | 已打开页面的日志和视频链接在项目副本清理后继续可用 |
| Task 确认完成 | `archivedAt` 起 30 天内保留报告与历史 | `waiting_review` 尚未开始这段保留期 |

运行中接口是快照读取，不是报告生成器或持续推送接口。业务 pytest 必须实际启用运行中报告写入，例如支持该设置的 pytest-html 配合 `-o generate_report_on_test=True`。尚未写出的结果、日志和视频无法预览。尚无托管版本的资源仍依赖源文件，资源尚未生成时返回 `404`；HTML 和单个运行中资源的现有限额为 64 MiB。

终态归档支持 MP4、MP3、M3U8、MPD、FLV、WebM 及文档列出的图片、分片和初始化资源。文件已归档与能在某台电脑播放是两项能力：编码、清单完整性以及浏览器和系统的解码能力都会影响播放。HEVC/H.265 尤其依赖客户端支持；HLS 的按需 MP4 兼容封装使用 FFmpeg stream copy，不会把不支持的编码转为 H.264，也不保证与 ffplay 的解码行为一致。

## 平台、Skill 与插件职责

| 组件 | 负责内容 |
| --- | --- |
| 平台 | Task/Session 生命周期、进程跟踪、轻量调度、Skill 归因、通用报告校验、预览、归档、Viewed 共享和保留清理 |
| 工作流 Skill | 选择业务流程、执行顺序、技术重试和业务 Rerun 策略，终态续接时决定下一步 |
| 测试/部署 Skill | 组装并启动业务命令，保存真实执行证据，登记每份已知 HTML，发布开始和终态报告 |
| pytest-html / video 插件 | 在正确 case 上生成 HTML、日志和媒体引用，保持本地相对链接可用，按所选模式准备项目媒体副本 |
| 外部存储管理 | 标准视频库、源视频和业务工作目录由操作者管理；当前策略不启动媒体备份 |

业务接入可使用自定义项目和标签，并复用通用 Step/Run、Schema v2 与后台登记协议。GW51、GW53、CICD/GW 部署和云录制失败分析顺序属于云录制工作流；平台不会因 `project=cloudRecord` 自动执行该流程。当前非终态报告的自动兜底仅覆盖文档列出的云录制测试和部署 Skill，其他业务应自行发布终态结论。

Skill 上报应使用 `schemaVersion=2`。`running` 报告必须提交 `artifacts=[]` 和关联的 `executionEvidence.externalAttemptId`；预览入口来自启动登记的 `--artifact`，不是在运行中报告顶层重复声明文件。终态继承登记 HTML，并显式追加后生成的分析文件。任务首轮冻结 Skill；更新源 Skill 或重启服务不会替换已有任务的快照，详见[上报协议](SKILL_REPORTS.md#发布)。

## 磁盘与部署边界

推荐媒体流转为：业务源媒体 → 项目 `task/<run-id>/videos` → 平台托管资源。报告和全部引用资源归档后，平台检查该 Run 的项目视频是否全部已有托管登记，满足条件才删除项目副本；未挂载文件会保留目录并留下原因。归档过渡期间可能暂时同时存在三份文件，清理后保留业务源与托管副本。平台不清理操作者管理的 `/data/jenkins/videos`。

运行库存提供“仅回收 Runtime”和“删除任务及产物”两种操作。后者支持非活动任务，包括已完成历史，删除该 Task 的平台记录、HTML、归档视频/音频/日志和播放缓存，再异步回收 Runtime。库存按任务展示 Runtime、归档产物、其他日志/快照及合计大小，没有 Runtime 的任务产物也会列出。文件大小估算不包含共享业务工作目录、源视频或数据库文件，硬链接在同一任务内按 inode 去重。普通 Task 删除不递归删除业务源目录；备份中的旧记录不会因在线删除立即消失。保留下来的已完成历史继续按 30 天策略处理。

当前部署面向单机 SQLite 与单节点 Worker，不提供跨主机 SQLite 集群或多租户隔离。任务分类和标签不构成权限分组。配置的工作目录根限制任务入口路径，实际业务命令权限仍由服务账户和部署环境决定。

修改 Node 后端后需重启服务才能生效；刷新浏览器只重新获取前端和报告快照。受控重启返回 `ok=true`、`ready=true` 且活动计数为零，才表示服务切换成功。

## 验证范围

2026-09-30 的受控重启和自测已验证服务 Ready、外部地址连通，以及 9 月 28 日任务 GW53 报告的托管与登记 URL 均可 GET/HEAD。无头 Chromium 已验证查看器使用实际文件名，并在沙箱 iframe 内渲染报告主体。

`test/skill-report-artifact-http.test.js` 与 `test/frontend-performance.test.js` 的 3 项测试通过，包含运行中 HTML 刷新按钮、空文件和终态不完整文件的响应检查。该次浏览器检查使用已结束的任务，运行中预览由隔离的 HTTP 测试验证；不据此宣称在线运行中 pytest、所有 case 日志或每种媒体编码均已逐项 E2E 验证。
